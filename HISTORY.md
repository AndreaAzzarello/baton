# Development history

A short diary of the work on Baton, newest first. For what changed for users see [CHANGELOG.md](CHANGELOG.md).

## 2026-11-04
- The buttons of a duplicate notification now work with Baton closed: the link starts Baton in the notification area, and once it is up it acts if the signature and expiry are valid and the download is still in the list ("expired" only otherwise). Offers for copied links stay valid only while Baton is open (`src/Baton.Core/Integration/LinkLauncher.cs`, `LinkActions.cs`, `src/Baton.App/Program.cs`, tests in `tests/Baton.Tests/ProtocolV4Tests.cs`).
- Spike: Native AOT cannot be linked here (no C++ linker), so the command line is published self-contained, single-file and trimmed: about 14 MB, no trim warnings; the MCP SDK also trims (about 19 MB with it).
- New `Baton.Protocol` project (messages, address helpers, pipe client, source-generated JSON, pipe naming) shared by the app and the new `batonctl` command line: add, list, status, pause, resume, retry, queues, open, remove, version, `--json`, exit codes 0-4, starts Baton in the tray when it is closed (`src/Baton.Protocol`, `src/Baton.Cli`, `tests/Baton.Tests/CliTests.cs`).
- `batonctl` ships with Baton: the installer adds it (and an optional "add to PATH" step, undone on uninstall), the portable zip and Scoop carry it, the release workflow builds and signs it, and the app's signed update package includes it so it updates with the program (`installer/Baton.iss`, `tools/build-packages.ps1`, `.github/workflows/release.yml`, `src/Baton.Core/Updates/ExtensionPackage.cs`).
- Version 1.4.0: changelog, roadmap, guides (save folders, duplicates, clipboard, command line, protocol 4) and `docs/CLI.md`; the extension, `Baton.exe` and `batonctl.exe` are 1.4.0.
- Real trials of the new windows (both themes), the duplicate and copied-link notifications (links run with Baton open and closed) and `batonctl` against an isolated app. Found and fixed: `batonctl add --no-start` queued the download instead of adding it paused (`DownloadService.Add` `paused`, test in `tests/Baton.Tests/ProtocolV4Tests.cs`); the duplicate dialog was too narrow for its four buttons (`src/Baton.App/Views/DuplicateWindow.xaml`). A trial-only switch (`BATON_TOAST_TRIAL`) lets a sandboxed run show real notifications and log them (`src/Baton.App/Services/ToastService.cs`).
- Installer trial on a copy of the script (own AppId and name): the `PATH` entry is added once, kept as an expandable value, removed on uninstall, and the real `PATH` stayed identical; portable trial checks that the `batonctl.exe` in the zip reaches the portable app (`tools/trials/portable-trial.ps1`). A list test moved dummy files into the real Downloads folder on every run; it now works under the test folder (`tests/Baton.UiTests/MainListCommandsTests.cs`).
- `batonctl` says why an address was skipped as a duplicate, in English or Italian (by the Windows display language), while the protocol and `--json` carry the stable codes `sameUrl`, `sameName`, `sameFile` (`src/Baton.Cli/CliText.cs`, `ControlHandler.ReasonCode`, `docs/CLI.md`). The trial switch for real notifications works only next to `BATON_DATA` (tested) and is documented in the `prova-reale` skill.
- Review of the stage (code and security; no security finding at high confidence). Fixed: `batonctl pause|resume|retry|remove '#5'` crashed; a failure inside a control message (a file type with no program) closed the connection without an answer, so the command line started Baton and sent it again, and a reply that did not come in time crashed it; `open` of a program or script is now only for the command line (`src/Baton.Cli/CliApp.cs`, `src/Baton.Core/Integration/ControlHandler.cs`, tests in `CliTests.cs` and `ProtocolV4Tests.cs`).
- Next: signing and release of 1.4.0.

## 2026-11-03
- 1.4.0 in progress. Fixed the project guard hook so a project path written as `~`, `$HOME` or `%USERPROFILE%` and the word "Desktop" inside a message no longer block commands (`.claude/hooks/guard.ps1`, `test-hooks.ps1`, `tests/Baton.Tests/Phase7Tests.cs`).
- IDM-style save folders: schema v9, one folder or a subfolder per type chosen in the wizard, Settings > Save in, per-download choice in the add dialog, move on recategorize (`src/Baton.Core/Categories.cs`, `DownloadService.cs`, `src/Baton.App/ViewModels/SettingsViewModel.cs`).
- Duplicate detection: same address, same name in the folder, same size and ETag after the server's answer (`src/Baton.Core/Duplicates/DuplicateDetector.cs`); history of removed downloads kept as a keyed hash, never the address (`src/Baton.Core/DownloadStore.History.cs`); entries that cannot ask skip and report a duplicate.
- Clipboard monitoring (off by default): a copied lone link to a known file type raises a tray notification that opens the add dialog; private clipboard content and Baton's own copies are ignored; the text is never stored or logged (`src/Baton.Core/Integration/ClipboardLinks.cs`, `src/Baton.App/Services/ClipboardWatcher.cs`, `TrayIcon.cs`).
- Added this diary and the rule to read its latest entries at session start.
- Protocol v4: the origin of a message (browser, command line, MCP, API) and what each may do; control messages for the command line (list, status, pause, resume, retry, remove from the list only, open, queues, version); the native host marks everything from the extension as browser (`src/Baton.Core/Integration/OriginPolicy.cs`, `ControlHandler.cs`, `MessageValidator.cs`).
- Notifications with buttons: a duplicate found at start (download anyway, open the existing file, remove) and a copied link (download, ignore, not for this site), as signed `baton:` links; the copied address is never in the link, only a short-lived in-memory reference (`ActionToasts.cs`, `LinkActions.cs`, `ClipboardOffers.cs`).
- Next: `batonctl` (step 6).
